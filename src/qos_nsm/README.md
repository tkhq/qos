# `qos_nsm`

`qos_nsm` contains QOS types and provider implementations for the AWS Nitro
Secure Module (NSM) API. QOS uses this crate to request attestation documents,
parse Nitro attestation documents, and verify the document fields that bind a
running enclave to an approved manifest.

The main abstraction is `NsmProvider`. Production code uses `Nsm`, which sends
`NsmRequest` values to the AWS Nitro NSM driver. Tests and local development
use a mock provider that implements the same trait.

## Providers

- `Nsm`: the production provider. It sends `NsmRequest` values to the AWS
  Nitro NSM driver and returns `NsmResponse` values from the driver.
- `MockNsm`: a test provider behind the `mock` feature. It tracks PCR state
  (seed via `MockNsm::with_pcr`, then `ExtendPCR`/`LockPCR`/`LockPCRs` behave
  like a real NSM) and answers every attestation request with a freshly
  signed COSE Sign1 attestation document over the current PCR bank that
  preserves the request's `user_data`, `nonce`, and `public_key` fields.

A provider also reports the root certificate authority peers should be
verified against via `NsmProvider::attestation_root_ca_der`. The default is
the AWS Nitro root CA; `MockNsm` overrides it with the mock root CA (below).
This keeps the trust anchor tied to the provider: enclaves running with a real
NSM only trust AWS-signed documents, while mock enclaves can fully verify
mock-signed documents with the exact code path used in production.

## Attestation parsing scope

The Nitro helpers in `nitro` expose two levels of parsing:

- `unsafe_attestation_doc_from_der` decodes the COSE payload into an
  `AttestationDoc` without certificate-chain or signature validation.
- `attestation_doc_from_der` validates the document syntax, verifies the
  certificate chain against a caller-provided trusted root, and verifies the
  COSE Sign1 signature against the document's end entity certificate.

Field-level verification against a manifest (user data, PCR0-3, and the QOS
manifest commitment PCRs) is layered on top via
`verify_attestation_doc_against_manifest_{setup,live}`.

## Mock PKI

`MockNsm` signs attestation documents with a static P-384 certificate chain
that mirrors the shape of the AWS Nitro PKI:

- `MOCK_ROOT_CERT_DER`: self-signed root CA. Verifiers that trust this root
  (e.g. via `MockNsm::attestation_root_ca_der`) can validate mock documents
  with `attestation_doc_from_der`.
- `MOCK_INTERMEDIATE_CERT_DER`: intermediate CA issued by the root.
- `MOCK_LEAF_CERT_DER`: end entity certificate; `MockNsm` signs with the
  associated key.

The fixtures are generated by `src/static/mock_pki/generate.py` and are valid
from 2020 through 2120 so they verify at both the fixed mock timestamp and at
wall-clock time (`mock_realtime` feature).

The mock root is never trusted by production code: the `mock` module is only
compiled with the `mock` feature, and `Nsm` always reports the AWS Nitro root
CA. Mock documents are for local development and tests only.
